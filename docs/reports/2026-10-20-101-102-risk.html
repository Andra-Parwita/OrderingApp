Risk review: plans 101 + 102

Fable, 20 Oct 2026, by reading the code (nothing changed). DellaVee has live customers, so the rule is: nothing existing may break; everything existing keeps working or falls back.

Verdict: safe to ship if three things stay untouched: each kitchen app's identity (id /<kitchen>), the current "Seller" app file, and a server-side redirect for every old order link. Nobody has to reinstall. If the safeguards can't all be built, ship the new routes and redirects first and narrow the app scope in a later release.

Escape hatch and rollback

  • Kill switch: the new "kitchen-only area" setting sits behind one server switch, on by default. If the tablet shows a problem, flip it back in minutes. Customers' apps update no sooner than their next day's launch, so they aren't reached before a flip.
  • Rollback: server only, no database change. Prefer the switch over rolling back the whole version: links made as /<kitchen>/o/… during the window would not open on 1.0.43.

Only a real device can show

  • When Android updates the installed apps, and whether a browser bar appears inside them
  • With two seller apps installed, which one opens a seller link
  • Samsung Internet's behaviour; iPhone icon names

Recommendation

  • Ship both 101 and 102 in 1.0.44 with the safeguards above, on a day with no open DellaVee menu.
  • First check after deploy, on the Samsung tablet: a fresh Onde Onde install (My orders, Settings, an order, no browser bar), then an old WhatsApp link and an old notification.
  • If the kill switch or the start-page test can't be built: ship the new routes and redirects only, keep the wide scope, and narrow it in 1.0.45.
