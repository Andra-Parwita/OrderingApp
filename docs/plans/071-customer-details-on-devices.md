# 071 · Delivery addresses: encrypted, team-only, short-lived; Directions; the seller's own address book

**Status:** approved (2026-10-13, owner "A"; ruling [D-099](../decisions/README.md), amends D-007 for addresses). Owner's path: customers add an address and the seller can launch Google Maps for directions, keeping privacy as much as possible → a master key, and if the key is lost the customer simply enters the address again → the message is in the kitchen's name, not ShaggyBobo's → "this will need a noob-friendly help section".
**Goal:** a customer can enter a **delivery address in the app**; it is stored **encrypted** with a server master key, visible only to **that kitchen's team** on the order with **Directions / Call / WhatsApp**, and **deleted automatically one day after the menu finishes**. The seller can keep a **long-term address book on her own device** (CSV backup reminder when a menu ends + upload to restore). Plain-words Help for sellers and customers.

## Rules
- **Customer checkout (delivery orders):** an optional **Address** field (multi-line, ≤ 300 chars), remembered on the customer's own phone for next time; the privacy line under it, with the full text behind "How we use this":
  - EN: "🔒 **Your address is kept safe.** {Kitchen} keeps it encrypted and uses it only to deliver this order and help you with it, never for advertising. Only {Kitchen}'s team can see it. It is deleted automatically one day after this menu ends. Want it removed sooner? Ask {Kitchen} on WhatsApp."
  - ID: "🔒 **Alamat Anda aman.** {Kitchen} menyimpannya secara terenkripsi dan hanya memakainya untuk mengantar pesanan ini serta membantu Anda terkait pesanan ini, bukan untuk iklan. Hanya tim {Kitchen} yang bisa melihatnya. Alamat dihapus otomatis satu hari setelah menu ini selesai. Ingin dihapus lebih cepat? Hubungi {Kitchen} lewat WhatsApp."
  - Editable until the cut-off like the rest of the order. The order note's helper text no longer says "don't add your address" (it points to the Address field instead).
- **A good address for Maps (owner "A", 13 Oct):** guided fields **Street number and name**, **Suburb**, **Postcode** (state from the kitchen's country default), plus **Notes for the driver** (unit, gate, "call when here"; shown on Deliveries, never sent to Maps); a **Check on map** button opens Google/Apple Maps on the typed address so the customer sees the pin; an optional **Use my location** button (Geolocation, only with permission) saves map coordinates. All of it is encrypted, team-only and deleted with the address (D-099). **Directions** uses the coordinates when present, else the address. No autocomplete service (no key, no cost, no keystrokes to Google).
- **Checkout flow (owner, 13 Oct):** the address section sits on the basket page under the Delivery choice. With **no saved address** on the phone it **slides open** when Delivery is picked (focus on Street; no animation with reduced motion) and **Next / Place order stay disabled until street, suburb and postcode are filled**. With a **saved address** it shows a compact card ("12 Jetty Road, Glenelg 5045 · blue gate", a map-pin note when coordinates are saved) with **Change** (the same form, prefilled) and **Use a different address** (keeps the saved one until a new one is placed). Back to Pickup hides it and keeps what was typed. Delivery-only menus open it straight away. State is left out (no kitchen/country default exists yet).
- **"See my address on the map" (owner "A"):** with the `MAPS_EMBED_KEY` variable set, it opens an in-app slide-in panel "Check your address" with a Google Maps Embed iframe (the exact location when added), then "Is the pin in the right place?" **Yes, looks right** / **Fix address**; without the key it opens the Maps app. The key is public (restricted by website in Google Cloud). The seller's Directions always opens the Maps app.
- **Delivery is done by the kitchen's own team only (owner, chef, helper); no sharing outside the team** (no "send to driver" button).
- **Map check inside the app (owner "A", 13 Oct):** "See my address on the map" opens a slide-in panel with a Google **Maps Embed API** map (free, no usage limit) and "Is the pin in the right place? Yes, looks right / Fix address". Needs a browser key `MAPS_EMBED_KEY` (not a secret; restricted by Google to our websites and to the Maps Embed API only). No key → opens the Maps app as before. The seller's Directions keeps opening the Maps app.
- **Changed address (owner "B", 13 Oct):** a customer may change the address (or the order) until the cut-off. The seller's order and Deliveries row show **"Address changed"** until a team member taps **"Got it ✓"**; the customer's order page then shows **"{Kitchen} has seen your new address"** ("Waiting for {Kitchen} to see your change" before that). The old address is never kept.
- **Server:** the address is encrypted with **AES-GCM** (Web Crypto, no library) using a master key from the secret **`ADDRESS_KEY`** (base64, 256-bit; `.dev.vars` locally, `wrangler secret put` live); stored as ciphertext + IV in a new column on the order (migration, add-only); decrypted only in seller-side reads for that kitchen's signed-in team (owner/chef/helper); **never** in customer menu responses, labels, print, the WhatsApp group post, logs, client error logs or backups (backup export omits it). Seller-entered orders (New order) may store the address the same way. Phone numbers stay **out** of the cloud (D-007).
- **Auto-delete:** addresses are wiped (set NULL) one day after the menu finishes (the hourly job), and when an order is cancelled; also a seller action "**Delete address now**" on the order. If decryption fails (key changed/lost), the order shows "Address not available — ask the customer" with WhatsApp/Call, and the customer's order page offers "Enter your address again".
- **Seller screens:** the address on the order detail (tablet + phone), a **Deliveries** list for the cooking day (name, address, items, **Directions** → `https://www.google.com/maps/dir/?api=1&destination=…`, Apple Maps offered on iPhone, **WhatsApp**/**Call** when the seller has the phone saved on the device), **Delivered ✓**.
- **The seller's own address book (device only):** IndexedDB on the device, `navigator.storage.persist()`; when a menu finishes, "**Back up your customer details?**" → `customers-<kitchen>-<date>.csv` (name, phone if saved on the device, address, last order date), "**Keep this file private**", no nag when nothing changed; Settings → **Customer details** → Upload CSV → add/update by phone (newer wins), never wipes.
- **Anonymous customer code (owner "A", 13 Oct):** the customer's phone makes a random code per kitchen the first time it orders there (stored on the phone; different for each kitchen, so kitchens can't link a customer across each other; no name/phone/email in it) and sends it with every order (an optional field; old apps send none). When the seller **confirms** an order whose code her device doesn't know yet, the app asks **"Link to a saved customer?"** with matches from her device address book (same or similar name) → **Link** / **New customer** / **Skip**. Once linked, the next orders with that code show the saved phone (Call / WhatsApp) and the address-book entry automatically. The CSV backup/restore carries the codes. A cleared or new customer phone means a new code: link once more.
- **Backup reminder (owner, 13 Oct):** only **when a menu ends and there is new or changed customer data on that device** ("3 new customers and 2 changed addresses since your last backup"); "Later" asks again next time the app opens; otherwise Settings shows "Up to date · last backup <date>".
- **Help:** Seller help topic "**Customer addresses and deliveries**" (where addresses are kept and for how long, Directions, the Deliveries list, back up and restore your address book, what happens if the key is lost, a "Keep it safe" box); Customer help FAQ "**Why does the app ask for my address? Who sees it?**"; the privacy text in customer Settings → About and privacy. Plain words, EN + ID.
