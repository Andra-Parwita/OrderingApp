Wireframes · batch 4 · sign-in and Saturday

Low fidelity, greys only. Grey box with a cross = image. Dark fill = primary, outline = secondary, dashed = disabled. Annotations name each action as Server (HTTPS to the app server) or Local / WhatsApp (stays on the phone, or opens WhatsApp and never touches the server). Sign-in screens drawn in EN; Indonesian versions needed later. Roles: admin, seller, chef (D-011, D-013). Draft 1, 2026-10-07.

  • The field is forgiving: spaces, dashes and lowercase are all accepted ("7qk4 m2xd 9ptr" works).
  • Server: "Continue" sends the key to be checked. A wrong, expired or used key gets one plain message, never a hint about which part was wrong.

  • Seller keys come from the admin, chef keys from the seller (S11); on success the next screen is A2.

C6 · Scan to collect

‹ Scan to collectENID

Type the order code instead
  • The camera is used only on this screen and stops when it closes.
  • Local: the QR is read on the phone; nothing from the camera is uploaded.
  • Server: once a code is read (or typed), the Server is asked about that one order and the result shows on C6b.
  • If the camera is refused, the screen falls back to the typed code.
