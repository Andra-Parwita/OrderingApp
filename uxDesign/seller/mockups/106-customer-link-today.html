Link to a saved customer: how it works today

Read-only explainer of the app as committed (HEAD), plan 071 / D-099. Kitchen: Onde Onde, Adelaide, AUD. EN text, with the ID wording in grey under it. No design proposal here.

What this is for

  • The server never stores phone numbers. Onde Onde's cloud cannot look up "Anin's WhatsApp".
  • Each seller device (tablet, phone, computer browser) keeps its own private list of customers: first name, WhatsApp number, address. It lives in that browser (IndexedDB, one database per kitchen). The tablet and the phone do not share it.
  • A customer code is a random 24-character code that the customer's phone makes for this kitchen only. It holds no name or number. It travels with each order, so the seller's device can tell "the same phone as last time". Another kitchen gets another code. A new or cleared customer phone gets a new code (a customer signed in with Remember me gets the code from their account instead; not confirmed end to end).
  • "Link" means: on this device, write that code into a saved customer, so the next order with that code shows the saved WhatsApp number.
  • Three things are easy to confuse, and they are separate: the order-row badge ★ New customer / ↩ Returning (set by the customer's phone), the window "Link to a saved customer?" (set by this device's list), and the "New customer" button inside that window.
0

When does the window open, and what do the badges mean?

Only when the seller presses Confirm on an order and the server accepted it, and the order has a customer code, and no saved customer on this device has that code. It does not open for orders without a code (old customer apps, orders the seller types with "+ New order"). It ignores the badge: a "↩ Returning" order opens it too if this device never linked that code. Derived from code, not tested: Undo of a cancel back to Confirmed takes the same path and may open it.

Order page banner: "Wait for their WhatsApp message so you have their number, then confirm." Tunggu pesan WhatsApp mereka agar Anda punya nomornya, lalu konfirmasi.
  • Returning: the customer's own phone has a collected/delivered order for this kitchen in its My orders and sent returning: true (D-027). Banner: "You can confirm without waiting." Anda bisa langsung konfirmasi tanpa menunggu. It has nothing to do with the seller's saved list.

6

The menu finishes: "Back up your customer details?"

When: the app is open on a seller screen; the latest menu is in state finished (a deleted, never-published menu does not count); this device's list has at least one customer new or changed since the last backup; and the seller has not pressed Later/Close since the app was opened. Each device decides from its own list.

"New" = created since the last backup (or never backed up). "Changed" = edited since. A customer made by "New customer" counts as new even with no phone.

Unduh cadangan · Nanti
  • Download backup: the browser saves customers-onde-onde-2026-10-17.csv (columns: first name, phone, street, suburb, postcode, notes, customer codes, last order date; the whole list, not only the changes). The device records "last backup: now". Counts drop to zero, so the window closes by itself, and Settings shows "Up to date · last backup 17 Oct 2026" Sudah terbaru · cadangan terakhir 17 Okt 2026. The file stays in Downloads; the app does not upload it.
  • Later / ✕ Close: closes it for this page load only; nothing saved. It returns the next time the app is opened, while unsaved changes remain and the finished menu is still the latest. Not "next menu".
  • The same actions sit under Settings (tablet) / More (phone), "Customer details": "Download backup (CSV)", "Upload CSV", the count and the last-backup line.

  • A row finds its entry by phone first, then by customer code; no match adds one. It never deletes or wipes. The newer "last order date" wins each field; an empty cell never clears a value; codes are always added together.
  • The codes come back in the file, so Anin's next order on this device finds her: no window, number shown. A row with no code is only found by phone.
  • A file without a "first name" column: "That file isn't a customer backup." File itu bukan cadangan data pelanggan.
  • derived, not run Restored rows look "new/changed" to this device, so the backup window may offer to back up what was just restored.
8

The browser clears storage

  • What happens: the list is gone on that device. The app asks the browser to keep it (storage.persist()), but clearing site data, a private window, or eviction still removes it. The backup counters go too. The next Confirm of every previously linked customer opens "Link to a saved customer?" again, usually with "No saved customer with a similar name.". Numbers are gone until a CSV is uploaded.
  • A warning that exists in the language files but that I found no code showing:

    This browser may not keep customer details after you close it.

    Browser ini mungkin tidak menyimpan data pelanggan setelah ditutup.
    Key customers.notKept. not confirmed in the working tree (I read HEAD only).
  • What the seller does see: only when saving a number or address on an order and the device cannot store it (storage blocked or no IndexedDB, so the list lives in memory): "This phone won't keep it after you close the app." Ponsel ini tidak akan menyimpannya setelah aplikasi ditutup. under the Contact block. Not in the Link or Backup windows.
  • Numbers kept by the older version in localStorage (sellerContacts.v1) are moved into the list when the app opens, as nameless entries.

Unclear points I noticed

  1. Two meanings of "New customer": the order badge (the customer's phone has no past order) and the window button (create a saved entry), same ID "Pelanggan baru"; a third use in "3 new customers" in the backup text.
  2. "Returning" and "saved" are unrelated: the badge comes from the customer's phone, the window from this device's list; a "Returning" order can still open the window.
  3. The title and intro don't say what linking does or why it matters (showing the number next time); "link" is jargon and the customer code is never named or shown there.
  4. "a phone this device hasn't met" mixes the customer's phone and the seller's device; ID says "pelanggan tetap" where the badge says "Langganan".
  5. "Same person, new phone" vs "different person" cannot be told from the matches list (name, number, address, last order only).
  6. New customer saves no number, and the window doesn't say the seller must type it on the order; the entry can stay empty yet still counts in backups.
  7. Link keeps the saved name (Lenny, not Lenni) with no feedback.
  8. Skip and Close are identical and silent; the question returns with no hint why.
  9. The window opens after Confirm (next to the Undo toast); it is not said that the order is already confirmed.
  10. Per-device lists are never explained; a seller on a second device just sees the question again.
  11. Backup reminder says "This menu is finished." but only appears when the app is next opened; Later lasts until reload, not next menu; Later and Close are the same.
  12. Several names for one list: "Customer details", "Customer contacts on this phone", older "Export/Import contacts" strings.
  13. Contradiction: the Contact block says "Saved on this phone only. Never sent to the server, and not in your backup.", but the CSV backup does include phone numbers and addresses.
  14. The "browser may not keep" warning appears unused (scenario 8); the only visible storage warning is on the order's Contact block.
  15. "Add to my customers" doesn't say it merges, never deletes, and brings back the codes that stop the window.

Not confirmed

  • Whether the notKept string is shown anywhere in the current working tree (HEAD only was read).
  • Whether Undo of a cancel re-opens the window (no undo check on the prompt in the saga).
  • Whether the saved name or number shows on the order row itself (only the WhatsApp/Call target and the Contact block use it in what I read).
  • Restore counting as "new" for the next backup reminder (from timestamps in code, not run).
  • Remember me giving one customer code across a customer's phones (read from customerAuth.ts, not run end to end).
  • Nothing here was run in a browser. The spec e2e/p071-customers.spec.ts only covers: Confirm, window, New customer, finished menu, backup window, Later.
